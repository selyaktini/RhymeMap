# Artist identification from metrics alone

Generated by `make eval` (`python -m eval.artist_id`). Do not edit by hand.

Engine: `similarity`. Features: density, multi, diversity, signatures, syllables.
Classifier: multinomial logistic regression, leave-one-out cross-validation, n = 12.

## Result

| | Accuracy |
|---|---|
| **Leave-one-out** | **0.0%** |
| Majority-class baseline | 25.0% |
| Chance (4 artists) | 25.0% |

The classifier **loses to** the majority-class baseline.

## Verdict: the claim is not supported

The metric vector does **not** identify the artist on this corpus. Every classifier tried, under both cross-validation schemes, lands at or below chance:

| Classifier | Leave-one-out | Stratified k-fold |
|---|---|---|
| logistic regression | 0.0% | 8.3% |
| 1-nearest neighbour | 8.3% | 8.3% |
| random forest | 0.0% | 8.3% |
| *chance* | 25.0% | 25.0% |

A one-way ANOVA per feature says why: no single metric separates the artists.

| Feature | F | p |
|---|---|---|
| density | 1.29 | 0.3425 |
| multi | 1.484 | 0.2907 |
| diversity | 0.206 | 0.8896 |
| signatures | 0.2 | 0.8935 |
| syllables | 0.09 | 0.9633 |

Every p-value is far above 0.05. Whatever these metrics measure, it varies more between two verses by the same artist than between artists.

Two things follow, and both matter for how the rest of this project is read:

1. **The sample is too small to conclude anything either way.** With n = 12 and 4 artists, one verse is worth 8.3% of the accuracy and each artist has only three examples. Leave-one-out is additionally biased against the held-out class when classes are this small: removing a verse leaves its artist with two examples against three for everyone else. That is part of why the figure is 0% rather than merely low. The honest reading is *no evidence*, not *evidence of no effect*.

2. **The existing artist-similarity and dendrogram figures should be read with this in mind.** `data/artist_similarity.png` and `data/artist_dendrogram.png` will always draw a clustering, because clustering algorithms always return clusters. This experiment is the check on whether that structure is real, and on this corpus it does not come out.

The best accuracy seen here is 8.3% against a 25.0% chance level. Settling the question needs a corpus one to two orders of magnitude larger; the pipeline already handles one via `make stats DATASET=path/to.csv`.
